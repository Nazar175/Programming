# Звіт до роботи
## Тема: Інтеграційне тестування
### Мета роботи: У цій роботі потрібно протестувати невеликий Flask-застосунок. Користувач створює завдання через HTTP-запит, застосунок зберігає його в SQLite, а потім експортує список завдань у JSON-файл. На відміну від юніт-тесту, тут ми не замінюємо базу даних і файлову систему mock-об'єктами. Тест використовує тимчасову папку та перевіряє повний сценарій від HTTP-запиту до збережених даних.

#### Команди встановлення залежностей і запуску тестів: pip install flask pytest

У тесті створення завдання перевіряється взаємодія Flask, SQLite та JSON. Під час отримання завдань Flask отримує дані з SQLite та повертає їх у форматі JSON. Під час перевірки порожнього списку та пошкодженого JSON тестується функція експорту даних у файл. У тесті порядку двох завдань перевіряється правильність збереження записів у SQLite. У тесті видалення перевіряється взаємодія HTTP-маршруту DELETE, бази даних SQLite та JSON-файла.

Під час виконання тестів було перевірено правильність HTTP-відповідей:
- Статус 200 — успішне отримання списку та видалення завдання.
- Статус 201 — успішне створення нового завдання.
- Статус 400 — повертається, якщо під час створення завдання не вказано поле title.
- Статус 404 — повертається, якщо завдання з указаним ідентифікатором не знайдено.
Також було перевірено фактичне збереження завдань у базі даних SQLite за допомогою SQL-запитів. Перевірка JSON-файла підтвердила, що після створення завдання дані правильно експортуються, порожній список зберігається як порожній масив, а пошкоджений файл перезаписується коректними даними.
